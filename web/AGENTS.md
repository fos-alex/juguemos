# Working on the web app

Rules for `web/`, on top of the repo-wide rules in the root [`AGENTS.md`](../AGENTS.md). Read both before changing anything here.

`web/` is the React SPA: Vite 7, React 19, TanStack Router file routes, plain JavaScript with JSDoc. Every 0.1 screen is built and runs on the API, and using the app needs a valid session. Before changing any UI, read [`docs/design.md`](../docs/design.md).

## Commands

```bash
npm run dev        # Vite at http://localhost:5173, no service worker
npm run build      # production build, to check it compiles; Caddy's image builds its own
```

`npm run dev` proxies `/api` to the Docker stack at `https://ludi.local:3000`, so signing in needs `docker compose up` ([README](../README.md)). The stack hot-reloads the mounted `web/` folder, so `ludi.local` and a phone both show a saved change without a rebuild.

**The service worker exists only in production builds.** In development Caddy answers `/sw.js` with a script that removes one left in the browser. To check the worker itself: `COMPOSE_FILE=docker-compose.yml docker compose up -d --build`.

**There are no automated tests yet.** Check changes in a browser at 390 px, signed in with a demo account, including offline, night mode, and reduced motion.

## Layout

```
index.html            the shell; no inline scripts
vite.config.js        router plugin, React, and the PWA manifest and service worker
public/               the app icon and the favicon, and the PNGs rendered from them
src/
  app/                the shell: main.jsx (router, service worker, first theme), the root layout
                      and its guard, ThemeProvider, the menu, updates
  routes/             one file per screen; the file name is the URL
  routeTree.gen.js    generated by the router plugin; never edit it, but commit it
  features/           one folder per module: account, family, voice, toys, materials, home,
                      activities, stories, admin
  shared/             what every feature uses and nothing domain-specific
    ui/               the primitives every screen is built from, each with its CSS next to it
    hooks/            browser APIs and screen patterns: back, online, wake lock, countdown,
                      theme, requests, saves
    store.js          the local store
    http.js           `request` and the errors every call can throw
    format.js         failures and times in words
    theme.js          the night-mode rule
  styles/             tokens.css and base.css, imported by index.css
```

## Import rules

Nothing enforces these; they are checked in review.

- **`app → features → shared`, never upward.** `shared` imports nothing from `features` or `app`, and a feature imports nothing from `app`, with one exception: `home` takes the menu from `app/AppMenu.jsx`.
- **A feature imports another feature only through that feature's `index.js`,** which exports its screens, its data functions, and its types. Nothing else in a feature is imported from outside it. Types cross the same way (the toy form takes `Kid` from `family`).
- **Routes import only from `app` and feature indexes.** A route file declares its URL and names a screen.
- **`home` is the one feature that composes others:** who's playing from `family`, the juego from `activities`, and the way into stories from `stories`.

## Routes

The router plugin turns `src/routes/` into the route tree. A dot nests the path (`familia.revisar.jsx` is `/familia/revisar`), `$id` is a parameter, `index` is a path's own screen, and `__root.jsx` wraps every screen. Each screen is its own chunk, preloaded on intent.

## How it fits together

- **The session guard** (`app/guard.js`) runs before each navigation from `routes/__root.jsx`, and again from `app/RootLayout.jsx` when the session may have ended. It awaits `ensureSession()` from `features/account/api.js`, which confirms the session with `/api/me` at most every five minutes and when the app returns to the foreground.
  - **A 401 signs the device out,** from that check or any other call: `request` in `shared/http.js` (and the story stream) calls `endSession()`, except under `/auth`, where a 401 means a wrong password. No answer at all — offline, weak signal, a server failure — keeps the cached account, so the last juego stays readable.
  - A device whose session ended goes to `/cuenta?modo=entrar`; one that never had an account, or signed out, goes to `/entrada`. `signOut()` waits for the API, since only the server can end the httpOnly cookie; offline it says so and the parent stays signed in.
  - **First run holds its order,** in `firstRunTarget()`: no account goes to `/entrada`, and no family to `/familia/contanos`. When `/api/me` says `familyFromText` is false (no LLM), no family goes to the form at `/familia/corregir` instead.
- **Build screens from the primitives** in `shared/ui/`, exported by its `index.js`, rather than one-off layouts: `Screen` (with `Header`, `Body`, `Footer`, `BackButton`), the buttons, `Card`, `Field`, `Chips`, `StepList`, `Drawer`, `Dots`, `Waiting`, `FinMark` and `PetalFall` (the one-off moments), `Skeleton`, `StatusLine`, `OfflineNotice`, `MetaLabel`, `Label`, `Wordmark`, `ThemeToggle`, and the icons in `Icons.jsx`. `Screen`'s `tone` sets the page background.
- **Screen patterns are hooks in `shared/hooks/`,** so no screen writes them again: `useRequest()` (`idle`, `loading`, `slow` after a delay, or `error` with the failure in words), `useOfflineNotice()` with `<OfflineNotice>`, `useSerialSaves()` for taps that save one after another, `useSlowWait()` for a wait that has gone on long enough to say something about, `useReducedMotion()`, and `useDocumentTitle()`.
- **Data comes only from each feature's `api.js`,** through `request` in `shared/http.js`. Screens never call `fetch` themselves and the web hardcodes no data. The two story streams and the voice upload call `fetch` directly, since `request` only speaks JSON, but they fail the same way. Screens work with the shapes in their feature's `types.js`, and `api.js` translates the API's shapes to them. `features/account/mock.js` holds only email verification.
- **Failures** go through `failureText()` in `shared/format.js`: the generic line, the offline line, or the words of a `WordedError` from `shared/http.js`. No error codes reach the screen.
- **Local state** is `shared/store.js`: one localStorage key per piece of state, listed in its `Key` typedef, read with `useStored(key)` and written with `write(key, value)`. It caches the account, the family, the toy box, the materials, activities, stories, the timer, and story positions, which is what keeps the last juego and the open story readable offline. The typedef groups keys by the feature whose `api.js` writes them; screens read any key but write through their feature's `api.js`.
- **A long wait animates** (JUG-132, JUG-133, JUG-160). `Waiting` is the waiting language for the waits that take long enough that the dots alone look frozen, drawn from the tokens. Two variants: `ronda`, the wordmark's dots holding hands, for every wait but a story's; and `drawing`, for a story being written. The drawing's `tool` follows the age the story is written for, through `waitingTool()` over `playingAgeMonths()` — a crayon under three, a pencil to five, a pen after that — and its `mark` is the story's interest mark from `interestMark()`, or the tool's own scribble when there is none. It shows the dots for the first moment, so a wait that ends at once never animates, and it shows the dots for good when the phone asks for less motion. It is `aria-hidden`, so the words beside it carry the meaning. `busyMark` on a button puts it in the dots' place there, and a place that needs it smaller sets `--waiting-size`. A wait that passes `SLOW_AFTER_MS` also says in one plain line what is happening, the way Home does under *¡Juguemos!*.
- **Voice notes** (JUG-95) are two parts. `features/voice/recorder.js` holds the microphone and `MediaRecorder` and knows nothing of React, so a native client can replace it. `VoiceNote` is the mic: hold to record, slide up to lock, slide left or lift on *cancelar* to drop, lift anywhere else to send. Its `children` can be a function given `record`, for a button beside the mic that starts a hands-free note on a tap (JUG-157). No sound, no confirm step, no playback. `haptics.js` gives a short vibration when a note starts, locks, is sent, or is dropped (JUG-135). The audio lives only in the component, only for a retry, and is never stored.
  - **A note the screen has to read** uses `VoiceUnderstanding` (JUG-103, JUG-146): it wraps `VoiceNote`, hands the words to the screen's `read`, and shows "Leyendo" beside the mic while that runs. The screen puts the answer where the parent confirms it, and nothing is saved before that: the toy candidates in the baúl, the form in Nuevo juguete, the form in Editar, and the story request on ¿Cuál leemos hoy? (JUG-156). `VoiceLine` is the one line a note shows when it couldn't do its part, with "Mandar de nuevo" when the same words are worth another try; a `WordedError` from `read`, like "no escuché ningún juguete", is shown as it is and without the retry.
- **Stories open before they are asked for** (JUG-140). Home requests the options in the background when it mounts online and none are stored, so *Hora del cuento* opens with them on screen. `storyOptions()` keeps the request it has out and hands the same promise to a second caller. The options are forgotten when who's playing changes. Both story streams share `openStream` and `readEvents`, and each option is written into the store as it arrives, so the cards fill in while the model is still writing.
- **A story is written for the youngest kid playing,** which is the rule the API anchors on. `playingAgeMonths()` gives that age, and the story screens use it to pick the waiting animation, so the wait is for the same kid the story is (JUG-132).
- **Series are the family's own** (JUG-59). `series` in the store holds the list the API last sent, so ¿Cuál leemos hoy? and the series screen show it offline; the API's answer replaces it. An episode is a story like any other, cached under its own id, and `Story.series` says which series and episode it is. The episodes of a series are not on the library shelf: they are read under their series, and a series the family stops following gives its stories back to the shelf.
- **Interest marks** (JUG-160). `interestMark(...texts)` in `features/family/model.js` gives the `MarkIcon` mark for the first text that names a common interest, or null. Interest chips show it through `Chips`' `lead`, and `StoryMark` puts it in the corner of a story card (`story-marked`) from the story's title and teaser, or a series' storyline. Never put it inside story text.
- **Interests belong to each kid** (JUG-144). `Kid.interests` are that kid's own; the family has no list. `playingInterests()` gives what the kids playing love, for the story keywords. A family cached by an older version has its family-wide interests copied onto every kid on the next load.
- **The feedback tap is two chips** (JUG-23). `ReactionRow` shows *¡Lo hicimos!* and *No era para nosotros* for a juego, one pressed at most; tapping the pressed one takes the reaction back. `reactToActivity` writes the store first and puts it back if the API refuses, so the chip answers the tap. It sits under the juego on `/idea/$id`, where a reaction can always be changed, and on Home under the last juego only while that juego has no reaction, staying through the tap so it doesn't vanish under the finger. Never a pop-up, never a sound, no counts.
- **Materials come from the API's list** (JUG-153). The categories, the materials, and which start marked are the API's; the web shows what `GET /family/materials` sends and saves one material per tap. A juego never needs a material the family has marked off, so the admin picks a template's materials from the same list.
- **Toys have an id in the family.** `Family.toys` is `{ id, name }`, and the family form sends each toy's id back: the API keeps what the toy box knows only about toys it recognizes, so a toy sent without its id comes back as a new toy with only a name.
- **Styles use the tokens** in `styles/tokens.css`. **Never write a hex value in a component or screen,** so nothing depends on a light background. A primitive's CSS sits next to it in `shared/ui/`, a feature's in `features/<name>/<name>.css`.
  - **The order is fixed:** `app/main.jsx` imports the tokens and base, then `shared/ui`, so the primitives' CSS always loads before a feature's and a feature can restyle a primitive at the same specificity (`.home__actions` over `.screen__footer`). In a production build, a feature the shell imports has its CSS in the main stylesheet; any other arrives with its screen's chunk. Check that an override still wins in a production build.
- **Night mode** is dark from 19:00 to 07:00 unless a one-tap choice still holds until the next switch. The rule is plain functions in `shared/theme.js`; `ThemeProvider` re-checks it at each switch and on returning to the foreground, then paints `<html>` and the status bar; `applyInitialTheme()` sets it once before React renders. Components read `useTheme()`. `?tema=oscuro` or `?tema=claro` counts as a tap.
- **Updates apply themselves** (`app/updates.js`). The page reloads at the next safe moment: never while a story is read or the timer runs, but once the parent leaves that screen or the app goes to the background. **A new screen a reload would interrupt goes in `BUSY` there.**
- **No inline scripts in `index.html`.** App logic goes in `src`, where it is built, cached, and reviewed with the rest.

## Adding a screen

1. Write it as `features/<feature>/screens/<Name>Screen.jsx` and export it from the feature's `index.js`. Read params and search with `useParams({ from })` and `useSearch({ from })`, since the screen doesn't import its route.
2. Add `src/routes/<path>.jsx` with only the declaration: `export const Route = createFileRoute('<path>')({ component: NameScreen })`, plus `validateSearch` when the URL has search params. No state, effects, JSX, or mapping.
3. Build it from the primitives and the hooks. Put its CSS in the feature's CSS file, tokens only. A screen over about 150 lines splits its parts into the feature's `components/`.
4. Set the title with `useDocumentTitle()`.
5. Get data from the feature's `api.js`, and cache in the store whatever must survive offline.
6. If it must be reachable before the family exists, update `firstRunTarget()` in `app/guard.js`.
7. Add it to the routes table above.

## Adding a feature

Every feature has the same layout, so there is one place for each file. A file a feature doesn't need is left out.

```
features/<name>/
  index.js        the public surface: screens, data functions, and types; nothing else is
                  imported from outside
  api.js          the endpoints, through `request`, and the store writes for this feature's keys
  model.js        pure logic with no React: form ↔ shape mapping, checks, text lines
  types.js        the shapes this feature works with, in JSDoc
  screens/        one component per route
  components/     pieces used only by this feature
  hooks/          when needed
  <name>.css      this feature's styles, tokens only, imported by its screens
```

Add the feature's store keys to the `Key` typedef in `shared/store.js`, under the feature's name.

## Calling a new endpoint

Write the function in its feature's `api.js`, calling `request` from `shared/http.js`. Translate the API's shape to the one in the feature's `types.js`, and export it from `index.js` only when another feature needs it. `request` throws `OfflineError` when the network fails and `ApiError`, with the status and code, when the API refuses, so screens and `failureText()` keep working unchanged. The endpoint's side is in [`api/AGENTS.md`](../api/AGENTS.md).

## Design rules that live in the code

[`docs/design.md`](../docs/design.md) has the whole set. These are the ones a code change undoes by accident:

- **Tokens only, never a hex.** The palette is the token set and nothing more. The one place hex is written out is `public/icon.svg` and `public/favicon.svg`, which are outside the app and can't read `tokens.css`; they change with the tokens.
- **Icons come from `shared/ui/Icons.jsx`.** Never write an `<svg>` in a screen or a feature: add the icon to the set, on the 24 px grid with a 2 px `currentColor` stroke, so it stays one weight and night mode needs no second drawing. `size` is the only prop worth changing. An icon is decorative (`aria-hidden`) and the button around it carries the label; an icon never replaces the words on a button.
- **No sound, ever,** including when the timer ends. The only vibration is the voice note's ticks (JUG-135).
- **Motion plays but never holds anyone up** (JUG-159). Use the motion tokens (`--motion-quick`, `--motion-moment`, `--motion-stagger`, `--ease-out`, `--ease-play`) and the shared keyframes in `base.css` (`rise-in`, `pop-in`, `slide-in`) rather than new values. Nothing waits for an animation, nothing loops except a wait, and nothing celebrates an achievement. Give an arriving animation `backwards` fill and keep its element visible at rest, so reduced motion (which `base.css` turns off everywhere) shows it in its final state. The moments are listed in `docs/design.md`.
- **The family's words stay exactly as typed,** so those inputs set `autoCorrect="off"` and `autoCapitalize="none"`.
- **Colour is never the only signal.** Flagged rows get a tint, a bar, and words.
- **Nothing that counts or compares:** no streaks, points, badges, percentages, or days since the family last played. The only progress bar marks position in a story.
- **Thumb zone:** primary actions in the lower half, tap targets at least 48 px, design width 390 px capped with `max-width`.
- **Copy is Rioplatense Spanish with *vos*.** What Ludi suggests is a *juego*, never an *idea*, and Home's button says "¡Juguemos!" (JUG-69). Copy still waiting on a voice pass is marked `Voice pass pending` in the code.
- **Out of scope for 0.1, so don't build it:** goals, categories and filters, weather, the journal, tips, recaps, holidays, the partner invite, post-activity feedback, and an English interface.

**Google sign-in** is hidden on the account screens until it arrives in 0.3; `GoogleButton` waits for it.
