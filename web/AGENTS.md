# Working on the web app

Rules for `web/`, on top of the repo-wide rules in the root [`AGENTS.md`](../AGENTS.md). Read both before changing anything here.

`web/` is the React SPA: Vite 7, React 19, TanStack Router file routes, and plain JavaScript with JSDoc. Every 0.1 screen from the Plaza handoff is built and runs on the API, and using the app needs a valid session. Only email verification is mocked, and Google sign-in waits for 0.3.

## Commands

Run from the repo root:

```bash
npm run dev        # Vite at http://localhost:5173, no service worker
npm run build      # production build to web/dist, to check it compiles; Caddy's image builds its own
```

- **The dev server proxies `/api`** to the Docker stack at `https://juguemos.local:3000`, so signing in needs `docker compose up`.
- **The local stack hot-reloads** (`compose.dev.yml`, turned on by `COMPOSE_FILE` in `.env`). At `juguemos.local` and on a phone, Caddy proxies to Vite's dev server on the mounted `web/` folder, so a saved change shows up without a rebuild. Rebuild (`docker compose up -d --build`) only after `package.json` changes.
- **The service worker exists only in production builds.** In development, Caddy answers `/sw.js` with a script that removes a production worker left in the browser. To check the worker itself, run the stack without the dev layer: `COMPOSE_FILE=docker-compose.yml docker compose up -d --build`.
- **There are no automated tests yet.** Check changes in a browser at the 390 px design width, signed in with a demo account (`npm run seed -w api`; the logins are in the README), including offline, night mode, and reduced motion.

## Layout

```
index.html            the shell; no inline scripts
vite.config.js        router plugin, React, and the PWA manifest and service worker
src/
  app/                the shell: main.jsx (router, service worker, first theme), the root layout and its guard, ThemeProvider, the menu, updates
  routes/             one file per screen; the file name is the URL
  routeTree.gen.js    generated by the router plugin; never edit it, but commit it
  features/           one folder per module: account, family, voice, toys, home, activities, stories, admin
  shared/             what every feature uses and nothing domain-specific
    ui/               the primitives every screen is built from, each with its CSS next to it
    hooks/            browser APIs and screen patterns as hooks: back, online, wake lock, countdown, theme, requests, saves
    store.js          the local store
    http.js           `request` and the errors every call can throw
    format.js         failures and times in words
    theme.js          the night-mode rule
  styles/             tokens.css and base.css, imported by index.css
```


## Import rules

Nothing enforces these; they are checked in review.

- **`app → features → shared`, never upward.** `shared` imports nothing from `features` or `app`, and a feature imports nothing from `app`, with one exception: `home` takes the menu from `app/AppMenu.jsx`.
- **A feature imports another feature only through that feature's `index.js`,** which exports its screens, its data functions, and its types. Nothing else in a feature is imported from outside it.
- **Routes import only from `app` and feature indexes.** A route file declares its URL and names a screen.
- **`home` is the one feature that composes others:** who's playing from `family`, the juego from `activities`, and the way into stories from `stories`.
- **Types cross features through the same `index.js`** (the toy form takes `Kid` from `family`).

## Routes

The router plugin turns `src/routes/` into the route tree. A dot nests the path (`familia.revisar.jsx` is `/familia/revisar`), `$id` is a parameter, `index` is a path's own screen, and `__root.jsx` wraps every screen. Each screen is split into its own chunk and preloaded on intent.

| Route | Screen (mockup id) |
|---|---|
| `/entrada` | Entrada (`2a`) |
| `/cuenta` | Crear cuenta (`2b`). `?modo=entrar` switches it to sign-in mode, and `?campo=email` focuses the email field |
| `/verificar` | Verificar el email (`2c`). Redirects until the API sends email |
| `/familia/contanos` | Contame de tu familia (`2d`), with the voice note (`2e`) on its mic |
| `/familia/revisar` | ¿Está bien así? (`2f`), or Entendió mal (`2g`) when the parse flags fields |
| `/familia/corregir` | Corregir (`2h`). `?campo=` focuses one field |
| `/familia` | Mi familia, the card's permanent home after onboarding |
| `/juguetes` | El baúl de juguetes (JUG-94): the toys by family name, and the household materials, which save on each tap. Built before the 0.2 design (JUG-84), from the primitives |
| `/juguetes/$id` | One toy: its name, other names, what it is, whose it is, favorite, the toys it goes with, and *Ya no lo tenemos*. `/juguetes/nuevo` adds one |
| `/ajustes` | Ajustes, not designed yet and kept minimal |
| `/` | Home: `2j`, or `2i` when there is no last juego. The drawer (`2k`), thinking (`2l`), and offline (`2q`) are states of Home. It is wider than the app (720 px) and may show how many templates are in use, but it still uses the tokens and the primitives.

## How it fits together

- **The root route** (`routes/__root.jsx`) runs the session guard, `app/guard.js`, before each navigation, and renders `app/RootLayout.jsx`, which holds `ThemeProvider` and runs the guard again when the session may have ended. Where the first run sends the parent is `firstRunTarget()`, a pure function in `guard.js`.
  - Before each navigation the guard awaits `ensureSession()` from `features/account/api.js`, which confirms the session with `/api/me` at most every five minutes and again when the app returns to the foreground.
  - A 401 signs the device out, whether it answers that check or any other call: `request` in `shared/http.js` (and the story stream) calls `endSession()`, except under `/auth`, where a 401 means a wrong password. The root layout sees the account go and runs the guard again. No answer (offline, a weak signal, a server failure) keeps the cached account, so the last juego stays readable offline.
  - A device whose session ended goes to sign-in (`/cuenta?modo=entrar`); one that never had an account, or signed out, goes to `/entrada`.
  - **Cerrar sesión** lives in Ajustes (the handoff's `2k`: Ajustes is account, not navigation). `signOut()` waits for the API, because only the server can end the httpOnly session cookie; offline it says so and the parent stays signed in.
  - Then the first run holds its order: no account goes to `/entrada`, and no family to `/familia/contanos`, where the parent writes about the family and the API's LLM reads it (JUG-11). When `/api/me` says `familyFromText` is false (no LLM is set up), no family goes to the form, `/familia/corregir`, instead.
- **Primitives** live in `shared/ui/` and are exported by its `index.js`: `Screen` (with `Header`, `Body`, `Footer`, and `BackButton`), `PrimaryButton`, `SecondaryButton`, `QuietButton`, `TertiaryButton`, `GoogleButton`, `Dots`, `Card`, `MetaLabel`, `Label`, `Skeleton`, `Field` (with `FieldControl`, `FieldGroup`, and `AS_TYPED`), `StatusLine`, `OfflineNotice`, `Chips` (with `ChipToggle` and `ChipInput`), `StepList`, `Drawer`, `Wordmark`, and `ThemeToggle`. Build screens from them rather than one-off layouts. `Screen`'s `tone` sets the page background.
- **Screen patterns are hooks in `shared/hooks/`,** so each screen doesn't write them again:
  - `useRequest()` is a request the screen waits on: `idle`, `loading`, `slow` after a delay, or `error` with the failure in words, and `busy` while it runs.
  - `useOfflineNotice()` and `<OfflineNotice>` repeat the offline line on each tap made offline.
  - `useSerialSaves()` saves each tap after the one before, and lets a later request wait for them (who's playing, the materials).
  - `useDocumentTitle()` sets the title.
- **Voice notes** (JUG-95) are the `voice` feature, in two parts. `features/voice/recorder.js` holds the microphone and `MediaRecorder` and knows nothing of React, so a native client can replace it. `VoiceNote`, which the feature's index exports, is the mic from `2e`: hold to record, slide up to lock, slide left or lift on *cancelar* to drop the note, and lift anywhere else to send it. It makes no sound and has no confirm step and no playback. `features/voice/haptics.js` gives a short vibration when a note starts, locks, is sent, or is dropped (JUG-135): `navigator.vibrate` on Android, and on iPhone a hidden switch's system tick, which iOS allows only from 17.4 to 26.4. The first time a device opens `2d`, `VoiceNote`'s `introduce` spotlights the mic behind a soft blur with a hint; pressing the mic or tapping elsewhere ends it for good (`voiceIntroSeen`). The words come back through `onText`, and the screen puts them where the parent checks them, the same as typed text. The audio lives only in the component, and only for a retry; it is never stored on the device. The states the handoff didn't design (transcribing, a denied mic, a browser that can't record, the service off, nothing heard, and retry) are one line under the text box, until the 0.2 design (JUG-84) replaces them.
- **Stories open before they are asked for** (JUG-140). Home asks for the story options in the background when it mounts online and none are stored, so *Hora del cuento* opens with them on screen; `storyOptions()` keeps the request it has out and hands the same promise to a second caller, so Home and the story screen never ask twice. The options are forgotten when who's playing changes, and the parent gets new ones with *Otras opciones*.
- **Data comes only from each feature's `api.js`,** all calling through `request` in `shared/http.js`. The two story streams — the options and the story itself — and the voice upload call `fetch` directly, since `request` only speaks JSON, but they fail the same way. `stories/api.js` opens both with the same `openStream` and reads both with the same `readEvents`: the options land one at a time and each is written into the store as it arrives, so the cards fill in while the model is still writing. Screens work with the shapes in their feature's `types.js`, and the `api.js` translates the API's shapes to them. `features/account/mock.js` holds only email verification. Screens never call `fetch` themselves, and the web hardcodes no data.
- **Local state** is `shared/store.js`: one localStorage key per piece of state, listed in its `Key` typedef, read with `useStored(key)` and written with `write(key, value)`. It caches the account, the family, the toy box, activities, stories, the timer, and story positions, which is what keeps the last juego and the open story readable offline. The typedef groups the keys by the feature whose `api.js` writes them; screens read any key but write through their feature's `api.js`. A new key goes in its feature's group.
- **Interests belong to each kid** (JUG-144). `Kid.interests` are that kid's own, and the family has no list of its own: the card shows a row per kid, or one row when every kid loves the same things, the form a chip group per kid, and `playingInterests()` gives what the kids playing love, for the story keywords. A family cached by an older version has its family-wide interests copied onto every kid on the next load.
- **Toys have an id in the family.** `Family.toys` is `{ id, name }`, and the family form sends each toy's id back: the API keeps what the toy box knows only about toys it recognizes, so a toy sent without its id comes back as a new toy with only a name. Each change in the toy box also updates the cached family's toys.
- **Failures** go through `failureText()` in `shared/format.js`: "Uy, algo falló. ¿Probamos de nuevo?", the offline line, or the words of a `WordedError` (from `shared/http.js`), such as an `AccountError`. No error codes reach the screen.
- **Styles** use the tokens in `styles/tokens.css`, which have light and dark sets. Never write a hex value in a component or screen, so nothing depends on a light background. A primitive's CSS sits next to it in `shared/ui/`, and a feature's in `features/<name>/<name>.css`, imported by its screens.
  - **The order is fixed:** `app/main.jsx` imports the tokens and base, then `shared/ui`, so the primitives' CSS always loads before a feature's. A feature can then restyle a primitive at the same specificity (`.home__actions` over `.screen__footer`). In a production build, a feature the shell imports (the guard takes `ensureSession` from `account`, which takes `loadFamily` from `family`) has its CSS in the main stylesheet, after the primitives; any other feature's CSS arrives with its screen's chunk. Check that an override still wins in a production build.
- **Night mode** is dark from 19:00 to 07:00 local time, unless a one-tap choice still holds until the next switch.
  - The rule is plain functions in `shared/theme.js`.
  - `ThemeProvider` re-checks it at each switch and when the app returns to the foreground, then paints `<html>` and the status bar.
  - `applyInitialTheme()` in `app/main.jsx` sets it once before React renders.
  - Components read it with `useTheme()`, which returns `{ dark, toggle }`. `?tema=oscuro` or `?tema=claro` counts as a tap.
- **No inline scripts in `index.html`.** App logic goes in `src`, where it is built, cached, and reviewed with the rest.
- **Updates apply themselves** (`app/updates.js`). Each deploy's service worker takes over on its own and deletes the old caches, and the page reloads at the next safe moment: never while a story is read or the timer runs, but once the parent leaves that screen or the app goes to the background. A new screen that a reload would interrupt goes in `BUSY` there. A chunk the new deploy replaced reloads the page instead of breaking it.

## Adding a screen

1. Write the screen as `features/<feature>/screens/<Name>Screen.jsx` and export it from the feature's `index.js`. Read params and search with `useParams({ from })` and `useSearch({ from })`, since the screen doesn't import its route.
2. Add `src/routes/<path>.jsx` with only the declaration: `export const Route = createFileRoute('<path>')({ component: NameScreen })`, plus `validateSearch` when the URL has search params. No state, effects, JSX, or mapping. The dev server regenerates the route tree.
3. Build it from the primitives in `shared/ui` and the hooks in `shared/hooks`. Put its CSS in the feature's CSS file, using tokens only. A screen over about 150 lines splits its parts into the feature's `components/`.
4. Set the title with `useDocumentTitle()`.
5. Get data from the feature's `api.js`, and cache in the store whatever must survive offline.
6. If the screen must be reachable before the family exists, update `firstRunTarget()` in `app/guard.js`.
7. Add it to the routes table above.

## Adding a feature

Every feature has the same layout, so there is one place for each file:

```
features/<name>/
  index.js        the public surface: screens, data functions, and types; nothing else is imported from outside
  api.js          the endpoints, through `request` from shared/http.js, and the store writes for this feature's keys
  model.js        pure logic with no React: form ↔ shape mapping, checks, text lines
  types.js        the shapes this feature works with, in JSDoc
  screens/        one component per route
  components/     pieces used only by this feature
  hooks/          when needed
  <name>.css      this feature's styles, tokens only, imported by its screens
```

A file a feature doesn't need is left out. Add the feature's store keys to the `Key` typedef in `shared/store.js`, under the feature's name.

## Calling a new endpoint

Write the function in its feature's `api.js`, calling `request` from `shared/http.js`. Translate the API's shape to the one in the feature's `types.js`, and export the function from the feature's `index.js` only when another feature needs it. `request` throws `OfflineError` when the network fails and `ApiError`, with the status and code, when the API refuses, so screens and `failureText()` keep working unchanged. The endpoint's side is in [`api/AGENTS.md`](../api/AGENTS.md).

## Design rules from the Plaza handoff

The spec is `docs/design_handoff_juguemos_plaza/`. Its README has the tokens, the type scale, and every screen. The mockups (`2a`–`2u`) are the spec, and the wireframes' notes (`1a`–`1t`) say what each screen must never do. Read the README before changing any UI. These are the rules that are easiest to undo by accident:

- **A tool for grown-ups, about play.** No mascot, character, or cartoon. The wordmark's three dots never get a face and never grow past splash size. Fredoka 600 is already at its limit: no heavier weight and no rounded body font.
- **No sound, ever.** That includes the moment the activity timer ends. No vibration either, except the voice note's short ticks, Alex's change (JUG-135), like a messaging app's.
- **Motion guides and never demands.** Use 120–200 ms ease-out with no bounce, spring, or confetti, and respect `prefers-reduced-motion`.
- **Flat.** No gradients, glossy or 3D buttons, or drop-shadow buttons. The palette is the token set and nothing more.
- **Never clinical and never a scoreboard.** No progress rings, streaks, points, badges, counts, percentages, "you stopped early", or days since the family last played. The only progress bar in the app marks position in a story. The timer never logs or compares sessions.
- **One juego, never a list or a feed.** The wait for a juego happens on Home, and Home's last-juego card is capped at one.
- **The family's words stay exactly as typed.** Toy names are never normalised, capitalised, or autocorrected, so those inputs set `autoCorrect="off"` and `autoCapitalize="none"`.
- **Colour is never the only signal.** Flagged rows use a tint, a bar, and words. The current drawer item uses a filled row.
- **No art on the reading screen,** even after 0.2 brings illustration. The wake lock holds from the moment a story starts being written until the parent leaves it.
- **Thumb zone.** Primary actions sit in the lower half, and every tap target is at least 48 px. The design width is 390 px, capped with `max-width`.
- **Copy is Rioplatense Spanish with *vos*,** taken verbatim from the mockups. Failures say "Uy, algo falló. ¿Probamos de nuevo?" with no blame and no error codes. Field errors go under the field, in words, never in a red banner. Offline is "Estás sin conexión. El último juego sigue acá." What Juguemos suggests is a *juego*, never an *idea*, and Home's button says "¡Juguemos!". That is Alex's change (JUG-69); the mockups still say *idea* and "¿Qué hacemos ahora?".
- **Copy still needs a voice pass** in these places, marked `Voice pass pending` in code: Listo, Prefiero un formulario, Guardar, the line after six seconds of thinking, Empezar, the timer screen, Jugando ahora on Home, Otras opciones, Modo noche and Modo día, all account-screen copy, all of the toy box, which the 0.2 design will also restyle, and the voice note's lines (`VoiceNote.jsx`, including its spotlight, and "Mandar de nuevo", "Reiniciar", and "Deshacer" on `2d`).
- **Out of scope for 0.1, so don't build it:** goals, categories and filters, weather, the journal, tips, recaps, holidays, the partner invite, post-activity feedback, and an English interface.
